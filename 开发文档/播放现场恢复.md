# 播放现场恢复

基于上游 v1.6.8，沿用现有的启动自动播放设置、播放引擎与保存频率。

## 本次改动

- 队列、当前索引、歌曲 ID、进度、播放模式和漫游 ID 作为一份 JSON 保存到 `playback_session_v2`，避免多个字段依次写入时混入不同歌曲的状态。
- 保存请求按调用顺序执行；清空队列也写入明确的空快照，防止旧版数据在下次启动时重新出现。
- 没有新版快照时读取 1.6.8 的 `playback_*_v1` 数据。新版快照损坏时安全放弃恢复，不回退到可能已经过时的旧队列。
- 恢复时过滤已删除、缺少 ID / 地址以及确定非音频的条目。保留原始索引对应关系，重复歌曲优先恢复到原来那一次出现的位置。
- 当前歌曲不再可用时，从原位置向后选择可用歌曲；没有后续歌曲则选择最后一首，进度归零。其他歌曲被过滤不会丢失当前歌曲的进度。
- 启动恢复尚未完成时，生命周期事件不会用引擎暂时上报的零进度覆盖已恢复的进度。

SharedPreferences 仍可能在进程被强制终止时丢失尚未完成的写入；此改动保证会话字段一起提交，不保证强制退出时最后一刻的进度落盘。旧版本不会读取新版快照，降级后可能恢复到旧版本最后保存的状态。

## 真机回归

1. 播放包含多首歌的队列，切到中间一首并播放一段时间。暂停、退出并重开，核对歌曲、队列顺序、进度与播放模式。
2. 分别关闭和开启启动自动播放，重开应用，确认是否自动出声符合设置。
3. 队列中重复加入同一首歌，播放第二次出现的位置；重开后确认索引没有跳到第一次。
4. 播放 CUE 曲目后重开，确认显示进度和实际声音都定位在该曲目内。
5. 开启随机漫游后重开，确认已有队列和漫游链恢复，下一首可继续播放。
6. 清空播放队列后重开，确认旧队列不再出现。
7. NAS 暂时不可达时重开，检查界面和恢复结果；恢复网络后手动播放，确认没有把另一首歌的进度带入当前歌。

网络、系统音频会话和原生引擎行为需要真机验证，存储单元测试不能代替这些检查。
